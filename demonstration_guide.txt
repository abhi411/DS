# Project Demonstration Guide: Customer Churn Prediction

This guide walk you through the end-to-end workflow of the project, from the business problem to the live API.

## 1. Business Problem & Data
- **Goal:** Identify which telecom customers are likely to cancel their service (churn) so the retention team can offer them incentives.
- **Data Source:** IBM Telco Customer Churn dataset (`data/TelcoCustomerChurn.csv`).
- **Show this:** Open the `data/` folder and show the CSV and the Data Dictionary to explain the different customer attributes (tenure, contract type, etc.).

## 2. Notebook Workflow (Preparation -> EDA -> Feature Engineering -> Model -> Evaluation -> Interpretation)
Open `notebook/churn_analysis.ipynb` and run through these sections:

- **Preparation:** Show how we handle the `TotalCharges` missing values (setting them to 0 for new customers) and the 70/30 train-test split.
- **EDA (Exploratory Data Analysis):** Highlight the charts showing that Month-to-Month contracts and Fiber Optic users are much more likely to churn.
- **Feature Engineering:** Show the `CleanAndEngineer` class. Explain how we create simpler categories (e.g., grouping "No internet service" into "No").
- **Model Training:** Show the Decision Tree setup. Explain why we used `class_weight='balanced'`—because catching churners (Recall) is more important than overall accuracy.
- **Evaluation:** Show the Confusion Matrix and the ROC-AUC curve. Point out that we catch ~82% of churners.
- **Interpretation:** Show the Decision Tree visualization. Explain how a human can follow the "branches" to see why a customer was flagged (e.g., "If tenure < 6 months AND contract is Month-to-Month...").

## 3. The Saved Model
- **Transition:** Explain that once we were happy with the model, we saved the *entire pipeline* (cleaning + the tree) into a single file.
- **Show this:** Point to `model/churn_model.pkl`. This file contains everything needed to turn raw customer data into a prediction.

## 4. The API (Deployment)
Now, show the model in action as a live service:

- **Start the Server:** Run `python app.py` in the terminal.
- **Health Check:** Open a browser to `http://127.0.0.1:5000/health` to show the model is loaded and ready.
- **Live Prediction:** 
    - Use the `sample_request.json` file.
    - Run the `curl` command (from the README) to send that data to the `/predict` endpoint.
    - Show the response: `{"prediction": "Yes", "churn_probability": 0.8821}`.
- **Input Validation:** Change a value in the JSON to something invalid (like `tenure: -5`) and show how the API returns a helpful error message instead of crashing.

## 5. Automated Testing
- **Reliability:** Run `python -m unittest discover -s tests` to show that we have 19 automated tests ensuring the API stays reliable even if we change the code later.
